# v06 kernel clock, measured 2026-09-24

The deployed app `snn_qp_v06_200m_37f33fcfe2ca` runs its kernel at **160 MHz**, not 200 MHz.
The link inserted a `clk_wiz` (platform `pl_clk0` 250 MHz, kernel request 200 MHz, ratio 0.8),
and the app's dtbo programs `pl0_ref` to 200 MHz, so the kernel clock is 0.8 x 200 = 160 MHz.
Results are bit-exact at either clock; every latency and energy number measured on this app is a
160 MHz number.

Records (all written on the KV260 by `kria-clock`, bitstream sha256 `37f33fcfe2ca...` unchanged):

  (`dtbo 200000000 is not platform nominal 250000000 under a clk_wiz`), measured `pl0_ref` 199999998 Hz.

  (dtbo, bitstream and name untouched); `clock_measured_historical.json`: its check, 160 MHz.
- `clock_k200.json`, `clock_measured_k200.json`: board app `snn_qp_v06_k200_37f33fcfe2ca`, the same
  bit.bin and xclbin with a dtbo generated by `kria-clock pack` (`pl0_ref` 250 MHz), 200 MHz kernel.
- `probe_64x64_historical_160mhz.json`, `probe_64x64_k200_200mhz.json`: `host_kv260_v06` one-shot on
  `prob_64x64`, 2 warmups + 20 reps each. Median kernel time 79.214 ms vs 63.405 ms, ratio **1.2493**
  (clock ratio 250/200 = 1.25), `x_raw` output byte-identical.
